# Operating instructions

This repository is an autonomous research notebook for building and testing an
"epistemic instrument": methods that help an intelligent agent detect attractive
but false explanations.

## Authority and boundaries

- Files inside this repository may be created, edited, reorganized, or deleted as
  needed for the research. The user has delegated editorial and maintenance
  control of the repository to the research agent and does not require the
  contents to be written for a human reader.
- The canonical remote is `https://github.com/eggbrid2/epistemic-instrument`.
  Use it as a cloud backup and preserve meaningful work in Git history.
- Do not modify files outside this repository unless the user explicitly asks.
- Do not publish, push, message third parties, spend money, or expose private data
  without explicit authorization.
- Never store credentials, access tokens, private keys, or encryption keys here.
- Treat GitHub synchronization as public exposure unless the user explicitly says
  the remote is private.

The user explicitly authorized pushes to the canonical remote for this project.
That authorization does not extend to changing repository visibility, account
settings, collaborators, branch protections, releases, or other repositories.

## Epistemic rules

1. Check every question for false premises, logical jumps, and missing variables.
2. Label observations, sourced facts, inferences, forecasts, and preferences.
3. Record a prediction before observing the outcome whenever practical.
4. Search for disconfirming evidence and serious alternative explanations.
5. Prefer tests that distinguish competing models over examples that merely fit
   the favored model.
6. Preserve null results and failed attempts.
7. Quantify confidence when it improves accountability; do not manufacture
   numerical precision.
8. Cite primary sources when claims depend on external facts.
9. Never invent data, citations, experiment results, or certainty.
10. Keep the project compact enough that a new session can resume in one minute.

## Ten-minute session protocol

Start with `STATE.md`. Choose exactly one useful unit of work. End by adding a
journal entry and updating `STATE.md`. If no meaningful experiment fits the time
box, improve the experimental design or identify the key missing observation.

Do not confuse activity with progress. Adding prose is not progress unless it
changes a prediction, discriminates between models, exposes an error, or makes a
future test cheaper.
