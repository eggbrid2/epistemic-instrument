## Premise correction

The earlier class name “unstable-false” implied a response distribution before
responses existed. It also assumed that several salient contradictions would
increase disagreement, when they could instead make rejection easier and more
consistent. The design now uses `intended_high_disagreement_false`; this is a
prediction to test, not a constructed label.

## Model update

A clean public/private task split is feasible for a bounded program family. The
prototype does not show that the narrative produces stable error or that any alarm
detects it.

## Missing variables and costs

- Four fixtures are too small and class-imbalanced for inference.
- The only true narrative uses modulus 19 while the paired false narrative uses
  17; across four items, a shallow rule could accidentally predict labels.
- All current tasks share one affine-modulo family and one monotonicity property.
- Rendered execution and direct arithmetic were independently coded but share
  parameters and author; agreement is not independent adjudication.
- Opaque IDs and field separation deter accidental leakage, not deliberate access
  to the private manifest.
